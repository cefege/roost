# Conformance vectors

## Session fold

`session-fold/*.json` has this shape:

```json
{
  "name": "opened",
  "events": [],
  "expect": { "sessions": [] }
}
```

`events` are JSON values accepted by `SessionEvent.parse`. `expect.sessions` is the
id-sorted array produced by `foldAll`; the runner compares it with `toEqual`.

## Cell chunks

`cell-chunks/*.json` has this shape:

```json
{
  "name": "single-complete",
  "chunks": [],
  "expect": []
}
```

`chunks` are canonical protobuf JSON values for `PbCellGridChunk`. Each expected
outcome is `pending`, `complete`, or `error:<CellGridChunkErrorCode>`, in input order.
The runner decodes each chunk with `fromJson`, pushes it through
`CellGridChunkAssembler`, and records the result or error code.

## Adding a vector

Add one JSON file, keep its name unique within its directory, and update the
throwaway generator when the fixture is derived from an implementation oracle.
Do not add tests that merely restate the JSON; the runner must exercise the
canonical parser, fold, decoder, or assembler.

## Terminal core

`terminal-core/*.json` drives a terminal emulator with a byte sequence and
records the state it must be in afterwards:

```json
{
  "name": "plain-text",
  "about": "what the bytes prove",
  "oracle": "xterm",
  "cols": 20,
  "rows": 4,
  "chunks": ["aGVsbG8="],
  "expected": {
    "viewport": ["hello", "", "", ""],
    "scrollback": [],
    "cursor": { "row": 0, "col": 5 },
    "alt_screen": false,
    "modes": {
      "cursor_keys_app": false,
      "bracketed_paste": false,
      "mouse_tracking": 0,
      "mouse_sgr": false,
      "focus_events": false
    }
  }
}
```

`chunks` are base64 of the RAW terminal bytes, which are UTF-8 — a wide glyph
is three bytes, and decoding as Latin-1 would drive a different terminal than
the one the vector names. An optional `resize` is applied after the chunks: a
resize is a separate wire event from a write.

Each vector records which oracle produced `expected`, and the three kinds mean
different things:

- **`xterm`** — generated by driving `@xterm/headless`, an implementation with
  nothing in common with this one. Passing says the core agrees with an
  independent terminal, which is a claim no test that asserts "whatever the core
  does" can make.
- **`patch`** — `expected` is written by hand from
  `scripts/wterm-0.5.0-roost.patch` and the vector names the hunk in `patch`.
  These are behaviours the v2 Zig core was patched to have and xterm does not
  share, so an xterm-derived vector would record the wrong answer. Where xterm
  happens to agree, the generator prints that; where it does not, it prints the
  two cursors side by side.
- **`known-divergence`** — the v2 core did something this core does not, and
  the gap is not closed yet. `expected` records what this core does TODAY and
  `diverges_from_v2` records what v2 did. The difference is asserted and
  greppable rather than silently wrong. **When a divergence is closed this
  vector fails, and the case is promoted to `patch`** — the failure is the
  reminder, not an obstacle.

Regenerate with `bun scripts/gen-terminal-core-vectors.ts`. A vector that
moved without its bytes moving is a behaviour change and deserves a commit
message that says so.

The runner is `crates/roost-term/tests/terminal_core_vectors.rs`; it drives
`AlacrittyCore` and asserts every field of `expected`, then prints the
outstanding divergences so a run cannot be read as "everything matches v2"
when it does not.
