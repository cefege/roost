# Pi Durable conformance oracle

Development-only differential oracle for the official Pi Durable implementation. It is not a Roost runtime dependency. The oracle identity is repository `https://github.com/earendil-works/pi`, commit `d5b3de22d0e24a3e9c38a9410d3329b099717283`, package `packages/durable`. That commit's package manifest reports 1.4.0, but published npm 1.4.0 is not an acceptable substitute for the pinned source checkout.

## Prepare the pinned upstream checkout

From the Roost repository root, obtain the immutable source in the ignored integration workspace:

```sh
if [ ! -d target/durable-integration.RMAHq5/pi/.git ]; then
  git clone https://github.com/earendil-works/pi target/durable-integration.RMAHq5/pi
fi
git -C target/durable-integration.RMAHq5/pi fetch origin d5b3de22d0e24a3e9c38a9410d3329b099717283
git -C target/durable-integration.RMAHq5/pi checkout --detach d5b3de22d0e24a3e9c38a9410d3329b099717283
test "$(git -C target/durable-integration.RMAHq5/pi rev-parse HEAD)" = d5b3de22d0e24a3e9c38a9410d3329b099717283
(cd target/durable-integration.RMAHq5/pi && npm ci --ignore-scripts)
```
`npm ci --ignore-scripts` installs the dependencies from upstream's checked-in lockfile without running package lifecycle scripts. The driver asserts the detached Git commit and refuses modifications in the pinned manifest, lockfile, and Durable/AI/Chord source trees. No upstream build artifacts, provider catalog generation, published `@earendil-works/pi-durable` package, or Roost runtime dependency is used.

## Generate and compare

From the Roost repository root:

```sh
node --conditions=source --experimental-loader ./tools/pi-durable-conformance/source-loader.mjs --experimental-strip-types ./tools/pi-durable-conformance/run.ts --write
node --conditions=source --experimental-loader ./tools/pi-durable-conformance/source-loader.mjs --experimental-strip-types ./tools/pi-durable-conformance/run.ts
```

Node 22.19+ runs the TypeScript with its built-in type stripper. The local loader routes package aliases to source files in the pinned checkout because the AI package has no `source` export condition; it avoids compiling the provider catalog or depending on generated `dist` files. The unsafe-interruption child uses the same loader.

Normalization omits the `timestamp`, `durationMs`, `startedAt`, and `endedAt` fields and maps only generated faux API identifiers of the form `faux:<milliseconds>:<nonce>` to `faux:<generated>`. Durable IDs, commit sequences, explicit tool-call IDs, ordering, content, errors, and usage remain exact. Every fixture embeds its upstream identity, normalization contract, normalized trace, and SHA-256 over the trace.

Generation executes the upstream implementation to completion before writing each fixture; comparison reruns those same scenarios and fails on any byte-level canonical JSON mismatch or missing/extra fixture. Fixtures are not hand-authored expected-success echoes.


## Native producer

The native producer depends on the shipped libraries in
`third_party/pi-durable-rs`, not a separate research checkout. It implements
the same 11 scenario names as the official-source oracle. Build both binaries:
the unsafe-recovery scenario launches and kills the companion child process.

```sh
flock /tmp/roost-cargo.lock cargo build --manifest-path tools/pi-durable-conformance/native/Cargo.toml --bins
for fixture in protocol/conformance/pi-durable/*.json; do
  tools/pi-durable-conformance/native/target/debug/pi-durable-conformance-native \
    "$(basename "$fixture" .json)" --compare "$fixture" || exit
done
```

The Rust comparator verifies the fixture envelope's upstream commit and trace
name before comparing native JSON with `trace`. It does not generate native
output from fixture data. A successful source build is not a conformance pass:
every scenario must execute and match independently.

Comparison is structural JSON: `1` and `1.0` denote the same number, but an
integer is never rounded to make it match a floating-point value. Array order,
missing fields, explicit `null`, and every nonnumeric value remain distinct.

## Coverage and limits

Traces cover plain/tool turns and request context/usage; busy steer/follow-up/reject/withdraw; SQLite reopen/dedup; `asOf`/`current`/`initial` fork policies; a child process killed with `SIGKILL` during an unsafe tool; generic task ownership/abort; persisted sleep/wake; nested task identity, keyed replay and structured error results; read-only observation; and deferred `pi.live` progress versus SQLite state. Fixtures are valid only after generated by running the pinned oracle.
