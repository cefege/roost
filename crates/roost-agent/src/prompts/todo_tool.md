Tasks are addressed by their exact task text, never by generated IDs. Use `view` to recover missing text. Keep task and phase names unique and stable; after every successful mutation the earliest pending task automatically becomes active if none is active. Starting a task moves any other active task back to pending. Completing a task immediately advances to the next pending task in phase order; never reopen completed work. Blocked tasks do not auto-start; `unblock` makes a task pending. Use one phase per meaningful stage and preserve every user-requested item as its own task. Never call `todo` alone: pair initialization or completion with the next concrete action.
