# v2 (Bun/TS) vs v3 (Rust) — speed benchmark, run 20261005-193858

- Machine: 6 CPUs, Linux 6.12.107+deb13-amd64 x86_64, 1-min load 1.00 at start; Chrome for Testing 151.0.7922.34 (`--headless=new`, 1280×800, fresh profile per round).
- v3: `c80fb611` — `target/release/roost` + `roost-keeper`, `wasm-release` web bundle. v2: `main` `48f6fa2f` — bun 1.3.14 from source, `vite build` SPA.
- Command: `roost-bench prepare`, then `roost-bench run --rounds 3` (3 rounds per stack, alternating v2, v3).
- Isolation: free loopback ports, fresh `HOME`, `ROOST_TERMINAL_PEER_ENABLED=0`; the page names the round's own worker door through the clients' `roost.localWorkerOrigin` override.
- Units: ms. `cpu_ms` is `/proc` utime+stime per role (10 ms ticks); RSS is summed per role. p50/p95 are nearest-rank; usage rows have one value per round, so their p95 is the max.

## Findings

- **Startup**: v3 coordinator listens in 33 ms vs 340 ms (0.10×); worker routable 97 ms vs 435 ms (0.22×); `SessionsSpawn` 17 ms vs 36 ms.
- **Server cost**: over the 200-keystroke echo run, v3 spends 50 / 220 / 40 ms CPU (coord / worker / keeper) against v2's 1250 / 1750 / 730. Idle RSS: 37 / 32 / 3 MB against 127 / 137 / 57 MB.
- **What the user sees is at parity**: echo p50 31.8 ms on both. Cold first paint 244 vs 255 ms (0.96×). Warm re-navigation is slower on v3: 200 vs 176 ms (1.13×). The 20k-line flood is faster on v3 (42 vs 61 ms). The 5k styled flood is slower at p50 (42 vs 32 ms) and faster at p95 (45 vs 60 ms). With four viewers, the slowest finishes in 40 vs 59 ms.
- **Browser cost is higher on v3**: the wasm renderer idles at 914 MB RSS against 818 MB (1.12×) and burns 3250 ms CPU across the echo run against 2530 ms (1.28×).
- **Caveats**: flood and echo times sit on multiples of ~10–20 ms, which suggests both stacks paint on a frame cadence `[INFERENCE]`. Sub-frame differences are noise at n=3. A navigation's first paint arrives over Sync or over the door, depending on whether the door was adopted yet; both stacks show both. Every flood ran on the loopback door on both stacks; the fan-out carrier is not recorded. No long tasks were observed on either stack.
